## 起動
`python -m http.server 4173 --directory dist`

依存なしの静的サイト。状態はメモリ内のみで、個人情報入力・成績保存・通信を伴わない。

### 校務PC（サーバーなし）での利用
`python3 build.py` で `dist/standalone.html` を生成。CSS・JS・全画像を埋め込んだ1ファイル（~10MB）なので、ダブルクリックして file:// でそのまま遊べる。GitHubからダウンロードするだけで動く。

## 構造
- dist/engine.mjs: ストーリー状態・カード定義・モンスター戦闘・分岐・効果・フリー行動・総合評価。DOM非依存。
- dist/app.js: 画面、ダイアログ、履歴、選び直し、資源変動アニメーション、任意のWebMCP。
- build.py: dist/ 以下を standalone.html（単一ファイル版）に束ねる。校務PC配布用。
- dist/style.css: レスポンシブ、日本語フォント、色以外での状態表示、モンスターパネル・バフ行・変動アニメーション。
- test.mjs: 分岐、資源境界、文脈依存効果、戦闘（撃破・反撃・場面の手数上限・大失敗）、ダーク/マイナスカード、バフのチェック。

## 画面構成（TRPG風）
教師がゲームマスターとして口頭で補足できることを前提にしつつ、必要な情報はアプリ内で完結させる。

- 左: システム系UI（ストーリー・身についた力=バフ/デバフ・目的・作戦ノート）
- 中央上部: モンスターパネル（名前・体力バー・残り手数=場面の時間・反撃力）
- 中央: 地の文と、他キャラのセリフ・様子、自分のこころの声
- 右: 「自分に問う」「話す・相談する」と、いつでも選べる行動
- 下: 扇形に持つ手札と、資源アイコン（手札枚数・行動力・精神力・評判）。数値の変動は拡大・色づき・浮き上がる差分で目立たせる

## 設計判断

### パラメータ
- 3資源: 行動力（0-5、カードのコスト）・精神力（0-6、0で大失敗）・評判（0-5）。評判は話す・相談・協力などの向社会的行動（`bond`）で増え、ダーク/マイナスカードで減る。上がるのは「できごと」（メイン・サブ問わず1イベントノード）につき1度だけ — 同じ場面で何度も目立ってもまわりの見方はそう変わらない。
- バフ・デバフ: かしこさ・運動能力・社交性（初期0、-2〜+2）。作戦カードを試すと同じ系統の力が+1（`up`）。マイナスカードは系統を下げうる（`dn`）。同じ系統のカードの攻撃力が、その力の分だけ上下する（`attr`）。
- バフ（`up`）・評判（`bond`）が育つのは試行の結果が出てから — 課題に届いた一手（ダメージ>0）か、そもそも課題を叩かないカード（攻撃0＝準備・内省系）のときだけ。空回りした一手では力も評判も育たず、育った力はその一手自体の攻撃力には含めない。

### モンスター戦闘
- 各場面には課題を象徴するモンスターが立つ。体力を0にする（課題を乗り越える）か、場面の手数を使い切る（時間切れ＝やり過ごす）と場面が進む。
- 1場面で出せるカードは3枚まで（`SCENE_PLAYS`）。カードを出す＝時間が経つ。モンスターを退けられていなければ残り手数を使い切るまで次へ進めない（出せる手がない場合のみフェイルセーフで進める）。退けた時だけ、残り手数の範囲でさらに手札を試すか次へ進むかを選べる。
- 課題モンスターは1つの状況につき原則1体。一つの状況から別種の困難が2つ以上立ち現れる話だけ複数体を持つ（例: なくし物=探すこと＋疑ってしまう心、体調を言えない=悪さ＋我慢しようとする気持ち）。
- 場面の終わり方で課題の行方が決まる： 討伐（体力0）・耐え抜く（手数が尽きて心を保つ）・敗れても力が育つ、は課題解決として先へ進む。心を削られて力負け（plain）した課題だけが、残りHPのまま次の場面に戻ってくる（「同じストレスが再来する」）。全部解決した後の残りの場面には「残ったモヤモヤ」（弱い名残）だけが残る。
- モンスターが残っていると反撃を受け、精神力が削られる。反撃は「気持ちがいっぱい」（精神力1）までは削るが直接倒さない — 大失敗は自分でコストを払いすぎた時だけ起きる。
- 評判0では反撃が+1される（まわりの目が冷たい）。向社会的に振る舞うことが防衛にもなる。
- 手数はカードを出した時だけ進む。マイナスカード・フリー行動・探索では進まない。

### できごと（サブイベント）
- 場面の合間に起きるおまけイベントは、一つひとつ固有の選択肢と結果を持つ。「失敗になる選択肢」「失敗に見えて実は正解」「正解に見えて失敗」「正しい考えでも力が足りず失敗する」4パターンが全体に散りばめられている（考え方が正しくても、うまくいかないこともある）。
- バフや評判、持っている手札を条件に選べる選択肢もある（`req`）。条件が足りない選択肢は見えているのに選べない — 最高の選択肢が見えていても、能力や準備、人づてが不足していると実行できない、という表現。

### カード
- 全カードは行動力コストと精神力コスト（`strain`）を持つ。
- ふだんの手札にも「怒る」「知らないふりをする」「勝ちほこってバカにする」などのダークカードが入る。精神力を回復するが評判が下がり、社交性も下がる。
- 精神力1以下では手札が赤いマイナスカードに入れ替わる。文句をいう・失敗する・やつあたりする・泣く・さぼる——場面ごと各1回で、出すと精神力が回復する。一部は系統の力を下げる（文句/やつあたり→社交性、失敗する→かしこさ、さぼる→運動能力）。回復はマイナスカード以外（少し休む・離れる・大人に相談）でも可能。
- バフ解禁カード: 力や評判が育つと、強い特別カードが手札に現れる（かしこさ→筋道を立てて説明する、運動能力→全力のひと押し、社交性→みんなをつなぐ声、評判→信頼のかけ橋）。黙って手札に混ぜるのではなく「新しい作戦を思いついた！」という獲得できごととして提示し、育った力に添える（脈絡づくり）。ただし使うにはさらに高い条件（`req`）が必要 — 見えているのに届かない状態を経て、力が育つと実行できるようになる。

### ふりかえり・総合評価
- 場面の合間に「お菓子をもらった」などのランダムなおまけイベントが起きることがある（約45%、精神力/行動力/評判/バフのどれかが+1）。
- 最後の結果はスコア制の評価（すばらしい作戦だった！/よくがんばった/もう少し作戦を広げよう/次は立て直しから）。数値合計は画面に出さない。
- 高評価パターン: 立ち向かって成功(+3)・敗れても力や評判が育つ(+2)・心を保って耐え抜く(+1)・大人に伝える/安全へ移る(+2/+1)。プレイヤーが社会的に望ましくレジリエンスの高い行動戦略を学ぶことが目的。
- 低評価パターン: 力負けの連敗でつく苦手意識(-2/系統)・評判の大きな低下・成長不足・精神力の低さの継続（「いつもしんどかった…」）・気持ちがいっぱいでの大失敗。
- 苦手意識（trauma）: 力負け（心を削られて敗退）が同じ系統で2度続くと、その系統のカードの気持ち消費が恒久的に+1される。敗北数・苦手意識は次の物語へ持ち越す（評判・精神力上限と同じ）。耐え抜いた・敗れても育った場面では連敗が切れ、つかない。
- 正のループ: 精神力を高く保つ→評判と手札を増やす→バフを盛る→モンスターを倒しやすくなる→さらに成長。
- 数値は架空キャラクターのモデルであり、児童の測定値ではない。
- 基本カードの選択は場面を進める。探索は各質問1回、休憩による回復は各場面1回。
- 「きき返す」「何もしない」は場面ごと各1回のフリー行動で、カードにはしない（いつでも選べるものは手札にしない、というメモの反映）。
- 精神力1以下（気持ちがいっぱい）では「話す・相談する」「自分に問う」は使えない。まず休む・離れて落ち着く — 焦っている時に深い話はできない、というメモの反映。
- 休憩・離脱・援助は手札・余力・気持ちの状態に依存しない。離脱や援助で振り返りに移る。
- 練習カードは運動会の負担理由（動き・他者評価・音）で効果が変わる。
- 会話の結果は固定分岐。相手の反応が常に思いどおりになる一般則を示すものではない。
- 学習効果は未検証。正式版には児童・支援者との試遊、文章や読み仮名の調整が必要。

## GAS（Apps Script）版

`node build.gas.mjs` で `gas/` 内に3ファイルを生成。Apps Script プロジェクトに同名ファイルとして貼り付ける:

| ファイル | 内容 |
|---|---|
| `index.html` | UIと束ねたJS（~320KB） |
| `img.html` | 全画像をdataURIで内蔵（~4MB。1行・貼るだけ） |
| `Code.gs` | `doGet` で配信 + `include` ヘルパ |

デプロイ手順:
1. script.google.com で新規プロジェクト → ファイルを追加して `index.html`・`img.html`・`Code.gs`（マニフェスト `appsscript.json` は「プロジェクトの設定」で表示してから置き換え）
2. デプロイ → ウェブアプリ → 実行ユーザー=自分、アクセス=全員（組織内だけにしたい場合は該当範囲に変更）
3. 発行されたURLを開く

画像は `img.html` にすべて内蔵しているため、GitHub Pages等の外部配信は不要。アプリ自体は静的JSなので保存データも外部送信もない。
